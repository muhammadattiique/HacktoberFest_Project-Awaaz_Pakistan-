# Multi-item complaint capture and multi-card verdict rendering

The change teaches the pipeline to extract every commodity a citizen names, persist one `Complaint` row per item under a single shared `submission_id`, and render each as its own verdict card. Previously a submission naming several items kept only the first (the aaloo+pyaaz driver dropped the onion). The approach keeps `parse_complaint_text` as a thin facade over a new `parse_complaint_items`, adds a collect-all rates resolver (`find_all_items`) that never falls through to the greedy fuzzy tier, and returns a new `MultiComplaintResponse` from both POST handlers while leaving the per-row `ComplaintResponse` shape backward compatible (only an additive `submission_id` field). The schema change is a single nullable indexed column added idempotently at startup. This is a convergence pass: the four findings from the prior review (`review.json`, CHANGES_REQUESTED) were all addressed.

Watch for: the ` bhi ` clause-split deviation that borrows the next price-only clause to attribute Rs 200 to pyaaz (confirmed, documented, correct); the out-of-scope faster-whisper engine swap bundled in the FEAT-001 commit (confirmed, documented as a required deviation for this machine); a large volume of unrelated benchmark/baseline artifacts in the same branch (confirmed, pre-existing from earlier Phase-0 commits, not part of this task's file set).

**Verdict**: APPROVED

## High-level view

Extraction is layered so an Ollama outage never costs a complaint. `parse_complaint_items` runs the LLM multi-item path and an always-on rule-only discovery pass, unions them by canonical id, and the deterministic rule price is the single source of price truth when present so a hallucinated LLM price cannot win. The whole method is wrapped to never raise and always yield at least one item; `parse_complaint_text` returns the highest-overcharge element so every existing single-item caller is unchanged, which the preserved test suite confirms.

Commodity discovery is owned by `RateService.find_all_items`, an additive public method that mirrors `resolve_item` tiers 1-3 but collects every distinct match and deliberately excludes the fuzzy tier-4, so discovery catches a second commodity instead of silently returning the first. `resolve_item` is untouched.

The schema gains one nullable indexed `submission_id` column, added idempotently via a `PRAGMA table_info` guard inside the same `engine.begin()` block as `create_all`, so fresh DB, already-migrated DB, and restarts are all safe and old rows load as `NULL`.

Both POST handlers delegate to one `_persist_submission` helper that generates a single `submission_id`, builds N rows, and commits them in one transaction (all-or-nothing). The voice handler keeps its entire temp-dir/FFmpeg/Whisper/503 path unchanged. The response carries the full `complaints` list plus an explicit `primary` (highest overcharge, urgency tie-break).

The frontend normalises both the new `{complaints,primary}` shape and a legacy single object, renders one `VerdictCard` per complaint under a count header shown only when there are multiple, and keeps the shared transcript and map rendered once from `primary`. Theming, RTL, per-card Copy-ID, and Replay-Voice are preserved; the i18n key is present in both locales.

The prior review's four findings are resolved: the CORS edit in `main.py` was reverted (file no longer appears in the diff), the faster-whisper swap is documented as a required deviation with its deps declared, the stray `DATABASE_URL` override is cleared (suite is 47/47 green), and the scratch DB files were removed.

### Fallback-first extraction and byte-compatible facade

`parse_complaint_items` computes `det_lang`/`rule_cat`/`rule_urg` once, segments the text into clauses, then builds two lists: the LLM list from `_call_ollama_llm_multi` (each raw item run through `_reconcile_item(has_llm=True)` with per-item clause attribution) and the rule list from `_discover_items_by_rules`, which always runs so an item the small model misses is still caught. The two are unioned by `item_canonical_id`. Rule rows are added first as the identity/price authority; when an LLM row shares a canonical id, its price only fills in when the rule price is not `> 0`, while category/urgency/native_response from the LLM are layered on. This matches the project's existing "rule price wins" precedence and is proved by a dedicated merge test. Unresolved (`canonical_id is None`) rows are kept only when no resolved row exists, so a spurious "Unspecified" row never sits beside real items.

The whole body is wrapped so any unexpected error returns the one-element safe fallback, and the empty-transcript branch returns the existing "Unspecified" dict. `parse_complaint_text` is now `return self.parse_complaint_items(text)[0]`; because the list is overcharge-sorted and always non-empty, the single-item observable output is unchanged — confirmed by the preserved `test_pipeline.py` assertions passing (47/47).

### Collect-all resolver without the fuzzy tier

`find_all_items` scans `_alias_map` under `self._lock` and collects every distinct `(canonical_id, item_dict)` whose alias (len >= 3) matches by exact/substring, de-duped by canonical id in insertion order. It deliberately omits `resolve_item`'s fuzzy tier-4 (which would fabricate commodities) and its single-return behavior (which would drop a second commodity in a run-on clause). `resolve_item` and `compare_price` are untouched. The driver works offline because both `aloo` and `pyaaz` are aliases in the rate list.

### ` bhi ` clause segmentation and price borrowing

`_segment_clauses` splits on sentence punctuation plus the enumerating connectives (` bhi `, ` بھی `, ` aur `, ` اور `, commas). For the driver this cleanly isolates the aaloo clause and the pyaaz clause. The connective split has a side effect: ` bhi ` separates "Pyaaz" from "200 rupay kilo", leaving the commodity clause without a price. `_price_clause_for` handles this by borrowing the immediately following clause for price extraction only when that next clause has a price and names no other commodity (`not rate_service.find_all_items(nxt)`). This is a deviation from the literal design that the implementer documented; it is correctly guarded so it cannot steal another commodity's price, and the driver test confirms pyaaz resolves to Rs 200 → official 120 → +66.7%.

### Single transaction persistence and explicit primary

`_persist_submission` generates one `submission_id`, builds one `Complaint` per extracted item with the shared audio/location/shop metadata spread via `**shared`, then `db.add_all` + a single `await db.commit()` + refresh — all-or-nothing (NFR4). `_select_primary` picks max `percentage_overcharge` with an urgency-rank tie-break, so the contract is explicit rather than relying on list order. Both handlers set `response_model=MultiComplaintResponse` at 201; the voice handler's temp-dir/FFmpeg/Whisper/400/503/`finally rmtree` path is unchanged and only its tail calls the shared helper.

### Driver contract verified by test

`test_api.py` posts the exact aaloo+pyaaz driver and asserts: `len(complaints) == 2`, a shared non-null `submission_id` on both, distinct ids, `aloo` reported 150 / official 100 / +50% / PERA, `pyaaz` reported 200 / official 120 / diff 80 / +66.7% / High, `primary.item_canonical_id == "pyaaz"`, shared `location_area`, and `submission_id` present on both the GET and PATCH responses. The single-item test reads `primary` and asserts `len == 1`. All green.

### Frontend multi-card rendering

`normalizeComplaintResult` returns `{submissionId, complaints, primary}` for both the new array shape and a legacy single object (wrapping a bare row), so the `/api/process-complaint` voice fallback still renders. `ReportSection` guards on `complaints.length > 0`, shows the count header via `replaceAll('{count}', …)` only when `> 1`, renders the shared transcript once from `primary.transcript_raw` and `MiniLocationMap` once from `primary` (guarded by lat/lng), and maps each complaint to a `VerdictCard`. The card preserves the rose/emerald theming keyed off `percentage_overcharge > 0`, the Badge variants, `formatPrice`/`formatVariance`, the `font-urdu` RTL branch, per-card Replay-Voice, and the `needs_review` notice; the dead `is_violation` term was dropped. Copy-ID state holds the copied id string so the checkmark lands on the right card. The avatar reaction is multi-item (chips capped at 6) and speaks only `primary.native_response`. Lint is clean and the production build succeeds.
